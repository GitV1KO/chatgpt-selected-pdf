# 架构与保真边界

扩展在用户点击浏览器工具栏按钮后，读取当前 ChatGPT 页面已经渲染的消息。勾选时在内存中保存消息的 DOM、计算样式及几何信息；导出时让 Chromium 重新渲染这些快照，再使用浏览器原生截图生成图像 PDF。它不把聊天重新解析为 Markdown，也不使用第三方服务排版。

## 模块

| 文件 | 责任 |
| --- | --- |
| `extension/manifest.json` | Manifest V3，只声明 `activeTab`、`scripting`，没有全站权限或常驻内容脚本 |
| `extension/background.js` | 工具栏入口、按顺序注入模块、截图会话验证、截图限速 |
| `extension/content.js` | 活动会话识别、消息身份与排序、多选面板、异步快照队列、路由清理 |
| `extension/snapshot.js` | 保存实际 DOM 的计算样式、伪元素、Canvas、几何框及内部滚动位置 |
| `extension/export.js` | 在隔离舞台重现快照、分片截图、避开文字行分页、停止与清理 |
| `extension/pdf.js` | 本地图像 PDF 写入器，RGB 像素使用无损 Flate 压缩 |

脚本在标签页的隔离执行环境中共享 `globalThis.CSPDF`。重复点击工具栏会打开已有面板，不会重复创建观察器。面板宿主是 `#cspdf-panel-host`，使用开放的 Shadow DOM；截图舞台是 `#cspdf-export-stage`，同样使用 Shadow DOM，层级高于原网页与面板。

## 截图授权

`chrome.tabs.captureVisibleTab()` 要求 `activeTab` 临时授权或 `<all_urls>`。本扩展采用前者。浏览器原生工具栏 action 或扩展快捷键授予访问当前标签页的权限；网页里注入的普通按钮不能独立授予它。扩展没有为了绕过这一限制申请全站权限。

工具栏入口校验目标是 `https://chatgpt.com/` 或 `https://chat.openai.com/`，随后调用 `chrome.scripting.executeScript()` 注入快照、PDF、导出和面板模块。实际截图由后台 service worker 执行。每个截图会话绑定标签页、窗口、URL 和过期时间；每次截图前后都验证它们仍匹配，且窗口处于前台。后台按至少 620 毫秒间隔串行截图，低于 Chrome 每秒最多 2 次的限制。

普通 SPA 会话切换仍可能在同源 `activeTab` 授权期内，但旧截图会话会因 URL 变化失效。扩展同时清空之前的选择，避免把两个聊天误混到同一 PDF。

官方说明：[activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)、[captureVisibleTab](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-captureVisibleTab)、[scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting)。

## 消息识别、身份与分组

面板首先选择当前 URL 对应、可布局且处于活动页面的对话根节点。旧会话可能仍挂在 `data-app-shell-active-page="false"` 的容器中，不能直接取页面第一个 `main`。

消息识别同时支持旧版 `data-message-author-role` / `data-turn`，以及带 `:user`、`:assistant` 后缀的 `data-chatgpt-search-unit-key` / `data-content-search-unit-key`。辅助角色标题只用于定位正文，不当作消息本身。无法确认角色时，不根据正文猜测。嵌套的语义包装层规范化为一个消息单元，优先采用真实消息 UUID 去重；不能拿相同文字代替相同身份。

“整组”按已经观察到的 DOM 顺序，把一个问题与它之后、下一个问题之前的回答归为一组。它只选择已经加载的对应消息，不能证明尚未渲染的分支、附件或历史内容已经包含在内。独立勾选始终可以只选择问题或只选择回答。

## 跨虚拟窗口排序

选择列表保留已经观察过的消息身份，但不长期保存未选消息的 DOM 子树。每次结构扫描记录相邻消息的先后关系，构成有向顺序图；相互重叠的虚拟窗口会通过共同消息连接起来。

明确的 `conversation-turn-N` 序号，以及 search-unit 中明确命名的 `conversation-turn-N`，可以连接没有重叠的窗口。尾部的消息单元序号、UUID、`fallback-turn-N` 和发现顺序不作为绝对时间顺序证据。若同一种序号与已观察 DOM 顺序冲突，就停用该序号来源。身份相同但序号改变、分支切换导致关系成环，也不会被静默当作可靠排序。

导出前要求所选消息之间存在可证明的先后路径。如果跨区域选择没有稳定序号、也没有重叠窗口连接，面板会显示明确提示并禁用导出。用户沿聊天连续滚动，让相邻区域重叠加载后重新识别，或减少跨区域选择，即可恢复。它不会把较晚发现的旧消息静默排到末尾。

## 快照队列与状态

核心内存结构如下：

```js
mounted: Map<id, { id, role, element, text, groupId, order, ordinal }>
selected: Map<id, { id, role, snapshot, text, groupId, order, selectedAt }>
pending: Map<id, requestToken>
errors: Map<id, reason>
```

`CSPDF.freeze(element)` 返回 `{html, node, styles, pseudo, width, height, background, lines, scrollStates, styleStats, ...}`，其中 `node` 是已移除脚本和事件属性的脱离原树 DOM 副本。保留节点结构，避免重新解析 HTML 时浏览器自动修复嵌套而改变布局。`content.js` 串行冻结，避免多个选择同时临时处理页面布局；请求令牌、会话代际和原节点身份用于丢弃已取消或过期结果。明确的生成中标记、冻结期间文字/子树/外观变化、节点卸载或复用都会使该条失败，要求等待回答完成后重选。

0.1.1 对相同的完整计算样式字符串去重，节点用 `data-cspdf-style` 关联共享规则；伪元素按类型与样式单独去重。没有按继承关系删属性，也没有降低公式或代码渲染质量。原行内样式会移除，冻结控制和根尺寸保留行内覆盖，Canvas 替换图片时保留共享样式 ID。导出器在 Shadow DOM 中同时注入普通样式与伪元素规则，并兼容已有的旧快照。容量检查包含 HTML、共享样式和伪元素的总字符量；`styleStats` 记录去重前后字符量，便于诊断普通长回答与实际过大消息。

快照完成后，原文被虚拟列表卸载或用户编辑原文不会改变已选结果。面板保留缓存摘要，并说明“已选内容保持勾选时外观；编辑后重选”。取消再勾选才会创建新快照。字体和图片可能需要等待，因此保存完成前会显示正在保存状态并禁止导出。

整组和批量选择逐条处理：部分失败时明确汇总成功、失败及实际已选数量。失败总数持续显示，不受搜索过滤影响。“只看已选”会清除搜索并列出完整选中集合，便于导出前核对。失败项不会被算入已选，也不会在 PDF 里静默产生空白替代页。

`CSPDF.app` 提供 `open()`、`scan()`、`stop()`、`getState()`、`destroy()`。`getState()` 包含当前顺序和顺序不确定原因，供本地测试诊断。

## 渲染、分页与停止

导出器收到按确认顺序排列的 `{id, role, snapshot}[]`，隐藏选择面板，在单独舞台恢复计算样式、伪元素和内部滚动状态。字体与图片就绪后核对快照布局，再按视口切片。截图按实际图像尺寸与 CSS 视口尺寸的比例裁切，不把设备像素比直接当作固定坐标比例。

舞台以克隆消息的实际 border box 对齐裁切区域，处理首段外边距折叠。几何检查排除已被裁切的屏幕阅读器辅助内容。代码区 sticky 工具栏恢复为正文流中的相对定位，避免重放旧滚动状态时覆盖其它文字；其自身和子元素的吸顶坐标不作为正文漂移。普通表格使用测量的列宽，避免 auto table layout 对已计算单元格宽度再次求解。环境背景取消息父辈颜色从外到内合成的不透明颜色，消息自己的半透明背景只绘制一次，保留圆角并防止未选页面透入；复杂祖先背景图会明确拒绝。

消息不会组成无限高 Canvas。导出器只保留当前 A4 页面画布，结合文字行、公式、图片和表格行的几何信息，尽量把页边界移到内容之间。消息保持原有宽度比例，过宽时为当前截图窗口等比缩小；在 A4 页面上仍可能因适配纸张而缩放。导出的 PDF 是图像 PDF，文字不能直接选择搜索，链接也不是可点击注释。

0.1.2 保留纸张外侧 10 mm 页边距，在 190 mm 宽的主题底色区域里再添加左右各 10 mm 的内边距，正文可用宽为 170 mm。截图本身不重排，原始正文宽度作为内容坐标；画布总宽和页高分别按 `190/170`、`277/170` 换算，水平居中放置内容，PDF 仍以 190 × 277 mm 绘制，避免横向拉伸。正文距纸张左右边缘约 20 mm；每页及末页都有同样的底色空隙。页数可能因统一缩放后的每页容纳量变化而减少。

舞台保留停止按钮，Esc 也可停止。切换标签、窗口、会话或调整窗口尺寸/缩放会停止导出，防止混入其他页面。临时舞台和截图会话在 `finally` 中清理；失败后保留已选快照供重试。

## 保真范围与限制

- 适用于浏览器已经完成渲染的正文、中文、普通 HTML 表格、代码高亮、SVG / MathML 公式、图片及可读取的 Canvas。
- Canvas 的绘制内容不会被 `cloneNode()` 复制，因此冻结时额外转成图片。受跨域保护而无法读取的 Canvas 会明确失败。[MDN cloneNode](https://developer.mozilla.org/en-US/docs/Web/API/Node/cloneNode)
- 冻结会保存计算样式与伪元素，再让 Chromium 重现。复杂的祖先选择器、特殊字体、封闭 Shadow DOM、滤镜、动画、交互控件和网页将来的结构变化仍可能导致差异；布局检查与人工视觉对照都需要保留。
- 图片仍在加载时会等待；已经显示为损坏图片的元素保留原有损坏外观。图片地址可能过期，或在重现时无法加载；这种情况会提示重新选择，而不能承诺远程图片永久可用。
- 不支持嵌入 iframe、音视频或插件内容的保真冻结。附件若只有可见卡片，只能导出卡片，不能取得未展开文件的正文。
- 内部横向或纵向滚动位置按冻结时保存。代码区未滚入视野的隐藏部分不会自动展开；展开会改变用户当时看到的外观。
- 超过单条 DOM / 快照内存限制，或超过 PDF 页数 / 大小限制时，会要求分批处理。不会为了完成导出而截断消息。
- 不通过网页未公开接口加载历史。网页未挂载、尚未加载的消息需要用户先滚动加载，且“当前加载”数量不代表服务端会话消息总数。

直接 `window.print()` 可以保留可选择文字，但浏览器打印样式、纸张宽度和分页会改变屏幕布局，因此本扩展不把它当作默认保真通道。[MDN Printing](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Media_queries/Printing)

## 观察与隐私

结构变化经过短延迟合并后重新识别。稳定消息中的流式文字、代码高亮等变化只更新受影响消息的摘要和变更版本，不重复扫描整个对话；面板自身及导出舞台的变化被排除。路由定时检查只比较路径与根节点，不定时重建所有消息。

扩展不读取 Cookie、令牌、私有应用变量或会话接口，不把聊天发送到第三方，不使用浏览器存储持久化聊天。快照和搜索词只存在当前标签页内存，刷新、关闭或切换会话后清除。重现已有远程图片时，浏览器可能继续向图片原地址请求资源；这不同于上传聊天内容，也不能宣称浏览器完全没有网络活动。

## 验证边界

自动测试使用隔离浏览器配置中的真实 Manifest V3 扩展、原生 action 授权与实际 `captureVisibleTab`，但 ChatGPT 文档由本地 fixture 提供。它证明扩展链路和已知布局，不证明账号中的所有真实会话与未来网页版本。真实登录会话还需检查消息标记、长历史虚拟化、分支、图片和数学排版，并把导出的 PDF 渲染为图片与网页对照。PDF 文件可打开、包含图片或页数正确，都不能单独证明视觉一致。
